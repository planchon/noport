---
title: "TLS configuration"
description: "Running the proxy on `https` and `wss`"
---

You can run the proxy using TLS and using a HTTP2 server. To do so, you need to generate and trust a root CA certificate. 

You own the private signing key. The key is store in `~/.noport/certs/ca.pem`.

<Note>
To run the HTTP2 server, you need to run the proxy in `https` mode.
</Note>

## Required tools
To generate and trust a root CA certificate we need `openssl` and `sudo`.

## Commands

### `setup` the certificate
Generate a root CA certificate and put it in `~/.noport/certs/ca.pem` (private key is generated in the same directory).


### `trust` the CA root certificate
<Warning>
If you do not trust the CA root certificate, you will not be able to run the proxy using TLS.
</Warning>

Trust the CA root certificate (requires `sudo`).

In theory, `noport` should not need sudo access to trust the certificate, this will be fixed in the future (you will be able to choose where you want to put the certificate).

### `nuke` the CA root certificate

In theory, keeping random, inactive CA certificate on your machine is not really a security issue. But you may want to `nuke` the CA root certificate (for any reason).
Nuking the certificate will : 
- untrust the CA root certificate
- remove the CA private / cert files
