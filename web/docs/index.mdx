---
title: "Why using NoPort ?"
description: "Change your local development by removing all the friction of ports managements."
---

NoPort solves many port related problems, increasong your productivity and your developer experience.

## AI workflows

A true vibe coder do not run only on instance of its app. 

He/she run multiple instances of the same app, one per agent / worktree. Reviewing the changes
from agent when the other are cooking.

Running multiple instance of the same app is a real pain, managing one big application is already complexe, imagine the horror of having to map each port to each subsystem of your massive application.

NoPort will detect the git worktree, or the git branch and serve your application on the right subdomain.

If you run 3 instances of your app in 3 differents worktrees, noport will give you 3 differents subdomains.
 - worktree `worktree_1` -> `https://app.worktree_1.localhost`
 - worktree `worktree_2` -> `https://app.worktree_2.localhost`
 - worktree `worktree_3` -> `https://app.worktree_3.localhost`

## Memorizing ports 

In big apps, you can have a lot of APIs and frontends, which means having multiple ports to remembers...

With noport you only have a simple, memoizable, domain. 

 - `3000` for the admin frontend -> `https://admin.localhost`
 - `3001` for the api -> `https://api.localhost`
 - `3002` for the user frontend -> `https://user.localhost`

<Info>Even better, your web browser will remember the domain, enabling auto-completion.</Info>

## `localhost` development

Using the `localhost` domain is a bad idea when you run multiple apps : all the cookies, local storage and other data are shared between the instances.

With one dedicated domain per app, you can have a clean development experience.

## TLS termination

Better parity with production: HTTPS on local mirrors real-world HTTPS behavior, headers, cookies (Secure flag), and browser policies.
