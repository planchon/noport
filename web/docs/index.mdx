title: "Why using NoPort ?"

NoPort solves many port related problems, increasing your productivity and your developer experience.
`noport` is particullary usefull when : 
 - you have a big application, running multiple processes (api, frontends...)
 - run multiple instances of the same app (with AI ✨ assisted coding)
 - you need TLS termination on your machine
 - you want a cleaner development experience 💅🏻

## AI workflows

True vibe coders runs many instances of their app, one per agent at minimum. You review the changes of one agent will the others are working hard. 

Running multiple instance of the same app is a real pain, as soon as you run your application twice, you will instantly run into `EADDRINUSE` errors.

To solve this problem, you will try to change the port, change the `.env` per instance... but this is a mess and do not scale.

NoPort will detect the `git worktree` or the `git branch` and serve your application under the right subdomain.

If you run 3 instances of your app in 3 differents worktrees, noport will give you 3 differents subdomains.
 - worktree `worktree_1` -> `https://app.worktree_1.localhost`
 - worktree `worktree_2` -> `https://app.worktree_2.localhost`
 - branch `feature/ai` -> `https://app.ai.localhost`

<Warning>
As `noport` is not yet in `v1` this feature is still at the moment, very experimental
</Warning>

## `localhost` development

### Host specific data (cookies, local storage) 

Using the `localhost` domain is a bad idea when you run multiple apps : all the cookies, local storage and other data are shared between the instances.

With one dedicated domain per app, you can have a clean development experience.

### Memorizing ports 

In big apps, you can have a lot of APIs and frontends, which means having multiple ports to remembers...

With noport you only have a simple, memoizable, domain. 

 - `3000` for the admin frontend -> `https://admin.localhost`
 - `3001` for the api -> `https://api.localhost`
 - `3002` for the user frontend -> `https://user.localhost`

<Info>Even better, your web browser will remember the domain, enabling auto-completion.</Info>

## TLS termination

### Parity with production

Better parity with production: HTTPS on local mirrors real-world HTTPS behavior, headers, cookies (Secure flag), and browser policies.

### HTTP2 support
Modern frameworks like Vite or Next makes a lot of request through the network, HTTP2 allow making a lot of requests in parallel, which means faster development.
Most proxy do not support HTTP2, so your app loading time will be slower.
